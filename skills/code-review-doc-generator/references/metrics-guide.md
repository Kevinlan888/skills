# 效率指标计算指南

> 此文件包含多维效率指标的计算公式和估算标准。在 Phase 5 生成文档时使用。

---

## 代码评审提效（核心指标）

量化 AI 评审相比人工评审的效率提升：

```
代码评审提效 = (预估人工评审耗时 - AI评审耗时) / 预估人工评审耗时 × 100%
```

### 人工评审耗时估算

根据代码变更规模和复杂度估算：

| 代码规模 | 行数范围 | 预估耗时 |
|---------|---------|---------|
| 小型 (small) | < 100行 | 10-30分钟 |
| 中型 (medium) | 100-500行 | 30-90分钟 |
| 大型 (large) | 500-1000行 | 1-3小时 |
| 超大型 (xlarge) | > 1000行 | 3小时以上 |

估算时综合考虑：
- 变更类型（新增/修改/删除）
- 文件类型（核心业务/普通代码/配置/测试）
- 代码复杂度

---

## 人工开发耗时估算

| 代码规模 | 行数范围 | 预估耗时 |
|---------|---------|---------|
| 小型 | < 100行 | 1-4小时 |
| 中型 | 100-500行 | 4-16小时 |
| 大型 | 500-1000行 | 2-5天 |
| 超大型 | > 1000行 | 5天以上 |

估算时综合考虑：
- 功能复杂度（算法逻辑/业务逻辑/简单CRUD）
- 技术难度（新技术/熟悉技术）
- 代码质量要求

### 开发效率提效

```
开发效率提效 = (预估人工开发耗时 - AI开发耗时) / 预估人工开发耗时 × 100%
```

仅当 `是否AI辅助 = 是` 时计算此指标。

---

## 问题摘出数统计

```
问题密度 = AI问题摘出数 / 代码总行数 × 100

已采纳问题率 = 已采纳问题数 / 首次发现问题总数 × 100%
```

## 代码质量维度

三个维度的评分标准（1-10 分）：

### 复杂度评分
- 分析：圈复杂度、嵌套深度、函数长度
- 评分越高表示代码越简洁

### 可维护性评分
- 分析：命名规范、注释覆盖、模块耦合
- 评分越高表示越易维护

### 安全性评分
- 分析：潜在安全漏洞、敏感数据处理
- 评分越高表示越安全

## 时间格式规范

北京时间（UTC+8）：

| 场景 | 格式 | 示例 |
|-----|------|------|
| YAML 时间戳 | `YYYY-MM-DDTHH:mm:ss+08:00` | `2026-05-15T14:30:00+08:00` |
| 文档显示 | `YYYY-MM-DD HH:mm` | `2026-05-15 14:30` |

## review_id 生成规则

格式：`CR-YYYYMMDD-NNN`

- `YYYYMMDD`：评审日期
- `NNN`：当日自增序号，从 001 开始
- 示例：`CR-20260515-001`
